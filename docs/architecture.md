# Архитектурное описание проекта Veltrix

## 1. Обзор системы
Veltrix — это сервисно-продуктовый маркетплейс, объединяющий продажу устройств, аксессуаров и предоставление услуг по их ремонту.

## 2. Архитектурный стиль
Система построена по принципу **Decoupled Architecture (Разделенная архитектура)**:
* **Backend:** Монолитное веб-приложение на Django REST Framework (DRF), предоставляющее RESTful API. База данных — PostgreSQL.
* **Frontend:** Клиентское приложение на Next.js (App Router), использующее серверный (SSR) и клиентский (CSR) рендеринг.

## 3. Назначение модулей бэкенда (apps/)
* **accounts:** Управление пользователями, профилями, адресами доставки и авторизацией.
* **catalog:** Модель данных товаров. Включает категории, бренды, конкретные модели устройств, продуктовые сущности (Product), торговые предложения (Variant), изображения и динамические атрибуты.
* **orders:** Корзина покупок, оформление заказов и управление позициями в заказе.
* **repairs:** Обработка заявок на ремонт (RepairRequest), сквозное логирование статусов (StatusEvent), выставление счетов/котировок (Quote) и каталог сервисных услуг.
* **core:** Общесистемные абстракции, кастомные middleware, глобальные исключения, базовые права доступа (permissions) и эндпоинт проверки здоровья (health check).

## 4. Потоки данных и интеграция
1. Клиент (Next.js) отправляет типизированные запросы на `backend:8000/api/v1/`.
2. Авторизация построена на базе JWT (передается в HTTP-only cookies или заголовке Authorization).
3. Межсервисное взаимодействие внутри Docker-окружения изолировано во внутренней сети.
